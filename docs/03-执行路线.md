## 决策记录（ADR）

| # | 决策 | 理由 | 放弃的方案 |
|---|---|---|---|
| ADR-1 | 完全重写，不继承 v1 代码 | v1 迭代混乱、无分层、无法维护 | 在 v1 上重构 |
| ADR-2 | PostgreSQL 单一可信源 | 多进程、可迁移、免费托管 | SQLite（锁+沙箱易失） |
| ADR-3 | Arq 而非 Celery | asyncio 原生、依赖少、cron 内建 | Celery（重）、APScheduler（进程内不可靠） |
| ADR-4 | 预测与资讯物理分表 | 杜绝"事后当预测" | 单表加字段（v1 做法） |
| ADR-5 | 盘面动量只展示不入模 | v1 实证 IC≈0，用户明确要求 | 技术面因子进权重 |
| ADR-6 | 先规则基线，后 GBM | 样本 900 条，复杂模型必过拟合 | 直接上 LSTM/Transformer |
| ADR-7 | LLM 只解释与抽取 | 可解释、可回测、成本可控 | LLM 直接给方向 |
| ADR-8 | Vant4 + 自定义 CSS | 移动端省时且不被组件库锁死 | Element Plus（桌面向） |
| ADR-9 | 按日分区 + BRIN，不用 TimescaleDB | 量小；避免扩展依赖与迁移风险 | TimescaleDB 起步 |
| ADR-10 | 单用户 Token 鉴权 | 个人项目，无需用户体系 | OAuth/JWT 多用户 |

## 给你的学习路径（顺便说）

企业级开发与"自己玩"的差别，不在用了多少组件，而在四件事：

1. **边界**：谁可以写库、谁只能读、谁可以调外部 API——写死在架构里，而不是靠自觉
2. **可复现**：任何结论能追到输入快照与版本号；回测与线上用同一条路径
3. **可观测**：系统出问题时，先看指标而不是猜；每个失败都有归属（源/任务/品种）
4. **可回滚**：上线不是单向门；模型、配置、代码都能一分钟退回去

这四条会在 M0~M7 里反复出现，跟着做一遍比看十篇文章有用。
