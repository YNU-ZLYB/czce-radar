# 02 · 数据模型与预测引擎

---

## 1. 数据模型

### 1.1 ER 总览

```
variety ──┬── quote_1m            (行情，按日分区)
          ├── daily_bar           (日线，回测用)
          ├── foreign_daily       (外盘日线)
          ├── inventory / basis   (产业指标)
          ├── seasonality         (季节性偏移)
          ├── news_sentiment_d  ( ← 由 news_doc/news_extract 聚合，滞后 1 日 )
          ├── feature_snapshot    ( ← 特征快照，唯一键 code+asof+version )
          └── prediction ──┬── prediction_revision
                           └── outcome
model_registry ── prediction.model_version
source ── fetch_log
llm_call_log / job_run / backtest_run / digest
```

### 1.2 核心表定义

> 全部时间字段：DB 内 **UTC naive**；接口输出 ISO8601 `Z`。金额/价格用 `NUMERIC(18,4)`，比率用 `NUMERIC(10,6)`。

```sql
-- 品种主数据
CREATE TABLE variety (
  code            VARCHAR(8) PRIMARY KEY,      -- MA / SR / CF ...
  name            VARCHAR(32) NOT NULL,
  sector          VARCHAR(24) NOT NULL,        -- 能源化工/油脂油料/软商品/黑色/建材/农副
  is_tradable     BOOLEAN NOT NULL DEFAULT TRUE,
  sort_order      INT NOT NULL DEFAULT 100,
  listed_at       DATE,
  delisted_at     DATE,                        -- 动力煤/小麦：is_tradable=false
  note            TEXT
);

-- 行情（分钟级；按日分区，BRIN(ts)）
CREATE TABLE quote_1m (
  id           BIGSERIAL,
  market       CHAR(1) NOT NULL,               -- 'D' 国内 / 'F' 外盘
  symbol       VARCHAR(16) NOT NULL,           -- SR701 / hf_OIL
  variety_code VARCHAR(8),                     -- 外盘为 NULL
  price        NUMERIC(18,4) NOT NULL,
  prev_close   NUMERIC(18,4),
  open/high/low NUMERIC(18,4),
  volume       BIGINT,
  oi           BIGINT,
  ts           TIMESTAMPTZ NOT NULL,           -- 行情时间
  source       VARCHAR(24) NOT NULL,
  created_at   TIMESTAMPTZ NOT NULL DEFAULT now()
) PARTITION BY RANGE (ts);
-- 每日子分区 + BRIN(ts)，保留 180 天，自动 drop 旧分区
-- 唯一键：source+symbol+ts（on conflict do nothing，天然幂等）

-- 日线（权威历史，回测与特征基座）
CREATE TABLE daily_bar (
  variety_code VARCHAR(8) NOT NULL,
  trade_date   DATE NOT NULL,
  open/high/low/close NUMERIC(18,4) NOT NULL,
  settle       NUMERIC(18,4),
  volume       BIGINT, oi BIGINT,
  source       VARCHAR(24) NOT NULL,
  PRIMARY KEY (variety_code, trade_date)
);

-- 外盘日线
CREATE TABLE foreign_daily (
  ext_code   VARCHAR(8) NOT NULL,              -- OIL/CT/S/SM/BO/C/W/NG/HG/DX
  trade_date DATE NOT NULL,
  close      NUMERIC(18,4) NOT NULL,
  change_pct NUMERIC(10,4),
  source     VARCHAR(24) NOT NULL,
  PRIMARY KEY (ext_code, trade_date)
);

-- 产业指标（仓单/库存/现货基差），kind 区分
CREATE TABLE industry_metric (
  variety_code VARCHAR(8) NOT NULL,
  trade_date   DATE NOT NULL,
  kind         VARCHAR(16) NOT NULL,           -- warehouse_receipt/inventory/spot/basis
  value        NUMERIC(18,4) NOT NULL,
  unit         VARCHAR(16),
  source       VARCHAR(24) NOT NULL,
  PRIMARY KEY (variety_code, trade_date, kind)
);

-- 季节性（人工核实后入库）
CREATE TABLE seasonality (
  variety_code VARCHAR(8) NOT NULL,
  month        SMALLINT NOT NULL,              -- 1..12
  stage        VARCHAR(32),                    -- 开榨季/入库季/检修季/旺季
  bias         NUMERIC(6,3) NOT NULL,          -- 负=偏空, 正=偏多（单位：信号分）
  confidence   NUMERIC(4,2) NOT NULL,          -- 0..1，人工把握
  note         TEXT,
  reviewed_by  VARCHAR(16),                    -- 用户核实标记
  PRIMARY KEY (variety_code, month)
);

-- 资讯原文
CREATE TABLE news_doc (
  id           BIGSERIAL PRIMARY KEY,
  source       VARCHAR(24) NOT NULL,
  external_id  VARCHAR(128),
  title        TEXT NOT NULL,
  content      TEXT,
  url          TEXT,
  published_at TIMESTAMPTZ NOT NULL,
  fetched_at   TIMESTAMPTZ NOT NULL,
  content_hash CHAR(40) NOT NULL,              -- 去重
  raw          JSONB,
  UNIQUE (source, external_id),
  UNIQUE (content_hash)
);
CREATE INDEX ON news_doc (published_at DESC);

-- 资讯结构化抽取（LLM 或规则）
CREATE TABLE news_extract (
  id           BIGSERIAL PRIMARY KEY,
  doc_id       BIGINT NOT NULL REFERENCES news_doc(id),
  variety_code VARCHAR(8) NOT NULL,
  direction    SMALLINT NOT NULL,              -- -1/0/1
  strength     SMALLINT NOT NULL,              -- 1..5
  chain_stage  VARCHAR(16),                    -- upstream/mid/downstream/demand
  is_surprise  BOOLEAN NOT NULL DEFAULT FALSE, -- 是否预期差
  method       VARCHAR(8) NOT NULL,            -- llm/rule
  model        VARCHAR(32),
  confidence   NUMERIC(4,2),
  evidence     TEXT                            -- 原文依据（可校验）
);

-- 每日资讯情绪（供 T+1 特征，严格滞后）
CREATE TABLE news_sentiment_d (
  variety_code VARCHAR(8) NOT NULL,
  trade_date   DATE NOT NULL,
  score        NUMERIC(8,3) NOT NULL,          -- 加权情绪分
  doc_count    INT NOT NULL,
  pos_count    INT, neg_count INT,
  PRIMARY KEY (variety_code, trade_date)
);

-- 特征快照（可复现的核心）
CREATE TABLE feature_snapshot (
  id          BIGSERIAL PRIMARY KEY,
  variety_code VARCHAR(8) NOT NULL,
  asof        TIMESTAMPTZ NOT NULL,            -- 生成时刻（=数据截止时刻）
  version     VARCHAR(16) NOT NULL,            -- 特征版本 f1
  features    JSONB NOT NULL,                  -- 见 §3 特征字典
  display     JSONB,                           -- 只展示不入模（盘面动量等）
  UNIQUE (variety_code, asof, version)
);

-- 模型注册表
CREATE TABLE model_registry (
  version     VARCHAR(24) PRIMARY KEY,         -- gbm-20261109-01
  kind        VARCHAR(16) NOT NULL,            -- rule/gbm/fusion
  params      JSONB,
  train_start DATE, train_end DATE,
  metrics     JSONB,                           -- 样本外指标
  status      VARCHAR(12) NOT NULL,            -- active/shadow/retired
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 预测（事前，唯一权威）
CREATE TABLE prediction (
  id            BIGSERIAL PRIMARY KEY,
  variety_code  VARCHAR(8) NOT NULL,
  target_date   DATE NOT NULL,
  horizon       VARCHAR(8) NOT NULL DEFAULT '1d',
  asof          TIMESTAMPTZ NOT NULL,
  direction     SMALLINT NOT NULL,             -- -1/0/1（震荡=0，由 bucket 推出）
  bucket        VARCHAR(8) NOT NULL,           -- 强空/偏空/震荡/偏多/强多
  p_up/p_flat/p_down NUMERIC(5,4) NOT NULL,
  exp_change    NUMERIC(10,4),                 -- 期望涨跌幅 %（= §5.1 raw_signal）
  signal        SMALLINT NOT NULL,             -- -100..100 规则分（§5.1，非 p_up-p_down）
  confidence    NUMERIC(5,4) NOT NULL,         -- 校准后置信度 = max(p*)
  contributor   JSONB NOT NULL,                -- [{name,value,weight,q,contribution}]
  model_version VARCHAR(24) NOT NULL,
  narrative     TEXT,                          -- LLM 中文解读（可空）
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (variety_code, target_date, horizon, model_version)
);

-- 盘中修订（有资讯驱动的方向修正）
CREATE TABLE prediction_revision (
  id            BIGSERIAL PRIMARY KEY,
  prediction_id BIGINT NOT NULL REFERENCES prediction(id),
  at            TIMESTAMPTZ NOT NULL,
  prev_signal   SMALLINT, new_signal SMALLINT,
  prev_direction SMALLINT, new_direction SMALLINT,
  reason        TEXT NOT NULL,
  trigger_doc_id BIGINT REFERENCES news_doc(id),
  is_surprise   BOOLEAN NOT NULL DEFAULT FALSE
);

-- 事后评分
CREATE TABLE outcome (
  prediction_id BIGINT PRIMARY KEY REFERENCES prediction(id),
  actual_change NUMERIC(10,4) NOT NULL,
  actual_dir    SMALLINT NOT NULL,
  actual_bucket VARCHAR(8) NOT NULL,
  hit_dir       BOOLEAN NOT NULL,
  brier         NUMERIC(8,6) NOT NULL,
  scored_at     TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 治理
CREATE TABLE source (
  code VARCHAR(24) PRIMARY KEY, name VARCHAR(48), kind VARCHAR(16),
  interval_sec INT, enabled BOOLEAN DEFAULT TRUE,
  last_status VARCHAR(12), last_error TEXT, last_run_at TIMESTAMPTZ
);
CREATE TABLE fetch_log (
  id BIGSERIAL PRIMARY KEY, source_code VARCHAR(24), status VARCHAR(12),
  fetched INT, inserted INT, error TEXT, duration_ms INT,
  started_at TIMESTAMPTZ NOT NULL
);
CREATE TABLE llm_call_log (
  id BIGSERIAL PRIMARY KEY, purpose VARCHAR(24), model VARCHAR(32),
  prompt_tokens INT, completion_tokens INT, cost_cny NUMERIC(8,4),
  cache_hit BOOLEAN, latency_ms INT, created_at TIMESTAMPTZ DEFAULT now()
);
CREATE TABLE backtest_run (
  id BIGSERIAL PRIMARY KEY, model_version VARCHAR(24),
  start_date DATE, end_date DATE, config JSONB, metrics JSONB,
  report_md TEXT, created_at TIMESTAMPTZ DEFAULT now()
);
CREATE TABLE job_run (
  id BIGSERIAL PRIMARY KEY, job VARCHAR(32), status VARCHAR(12),
  started_at TIMESTAMPTZ, finished_at TIMESTAMPTZ, detail JSONB
);
```

### 1.3 为什么这样拆

| 设计 | 解决的 v1 问题 |
|---|---|
| `prediction` 与 `news_extract` 分表 | E1：预测永远不依赖当天资讯；资讯只是独立事实 |
| `feature_snapshot` 落库 | E2：回测与线上共用同一份输入，杜绝"回测时偷看" |
| `contributor` JSONB + `model_version` | E3/R-05：每个数字都能追到权重来源 |
| `prediction_revision` 只追加 | 修订历史可审计，可回答"盘中为什么翻空" |
| `outcome` 独立表 | 上线即开始积累评分，模型效果不靠嘴说 |
| 分区表 + BRIN | 分钟行情长期存储不炸，查询仍然快 |

## 3. 预测目标定义（最重要的一节）

### 3.1 预测什么

- **时点**：T 日 08:30（开盘前）
- **目标**：T 日收盘价相对 T-1 收盘价的涨跌幅 `r`
- **输入**：≤ T-1 收盘的国内数据 + 隔夜外盘 + 产业指标 + 季节性 + T-1 资讯情绪
- **绝不使用**：T 日任何盘中价格、T 日任何资讯

### 3.2 三分类 + 幅度分档（按品种波动率自适应）

```
σ = 该品种过去 20 个交易日的日收益标准差
震荡带 = max(0.5%, 0.35 × σ)
强档带 = max(2.0%, 1.00 × σ)

r >  强档带        → 强多
震荡带 < r ≤ 强档带 → 偏多
|r| ≤ 震荡带        → 震荡
-强档带 ≤ r < -震荡带 → 偏空
r < -强档带        → 强空
```

用 σ 自适应而不是死阈值的原因：白糖日波动 0.6%、甲醇 3%，同一个 1% 阈值对两者含义完全不同。

### 3.3 输出契约

```json
{
  "variety_code": "MA",
  "target_date": "2026-11-10",
  "asof": "2026-11-10T00:30:00Z",
  "direction": -1,
  "bucket": "偏空",
  "p_up": 0.21, "p_flat": 0.27, "p_down": 0.52,
  "exp_change": -1.42,
  "signal": -31,
  "confidence": 0.52,
  "contributor": [
    {"name": "布伦特", "value": -1.31, "weight": 0.45, "q": 0.58, "contribution": -8.4},
    {"name": "NYMEX 天然气", "value": -0.62, "weight": 0.30, "q": 0.58, "contribution": -2.7},
    {"name": "季节性·11月限气", "value": null, "weight": 1.0, "q": 0.5, "contribution": 3.0},
    {"name": "资讯情绪(T-1)", "value": -0.2, "weight": 0.2, "q": 0.3, "contribution": -1.2}
  ],
  "model_version": "fusion-20261109-01",
  "narrative": "隔夜布伦特跌 1.31%，油制甲醇成本下移；天然气同步走弱，成本端双重压制。国内 11 月限气尚未兑现，暂不构成支撑。"
}
```

**展示口径**：卡片大字显示 `bucket`（如"偏空"）+ `|signal|`（31），颜色按方向。**不再叫"强度 82.9"这种无源之水**。

### 3.4 置信度与校准

- 原始置信度 = `max(p_up, p_flat, p_down)`
- 校准：在最近 60 个样本外交易日上做 isotonic 回归 → `confidence`
- 可靠性要求：置信度 0.6 的预测，实际命中率应在 0.55~0.65
- 事件日折减：T 日有重大事件（OPEC、USDA、交割周、政策发布）→ `confidence × 0.8`，并在卡片标注「事件日」
- 数据缺失折减：外盘数据缺失 > 2 个源 → `confidence × 0.7`

## 4. 特征字典（严格 asof）

快照结构：

```jsonc
{
  "asof": "2026-11-10T00:30:00Z",
  "price": { "close": 3136, "ret_1d": -0.012, "ret_5d": 0.031, "vol_20d": 0.021, "pos_20d": 0.18 },
  "foreign": {
    "OIL": {"chg_1d": -1.31, "chg_3d": -2.10, "session": "prior"},
    "NG":  {"chg_1d": -0.62, "chg_3d": -1.02}
  },
  "linkage": [ {"ext": "OIL", "prior": 0.45, "q": 0.58, "contrib": -8.4} ],
  "industry": { "receipt_chg_5d": 0.021, "inventory_pct": 0.72, "basis_pct": -0.013 },
  "seasonality": { "month": 11, "bias": 3.0, "stage": "限气预期", "confidence": 0.5 },
  "news": { "sentiment_lag1": -0.2, "count_lag1": 7 },
  "event": { "is_event_day": false, "tags": [] },
  "display_only": { "spark_6h": [3130, 3136], "volume_ratio": 1.12 }
}
```

**关键约束**：
1. `asof` 是快照唯一时间戳，任何字段的数据时间必须 ≤ asof；
2. `display_only` 块**永不进入模型**（盘面动量、量能、K 线形态）——用户明确要求；
3. `news.sentiment_lag1` 只取 ≤ T-1 的资讯；
4. `foreign.*.session == "prior"` 表示只用前一交易时段的外盘收盘。

**为什么保留 `display_only`**：盘面数据对"人看"有价值（知道市场在动），但对"报方向"无价值（v1 实证 IC≈0）。分开存储，展示与建模各取所需。

## 5. 模型方案（三层递进）

### 5.1 Layer A · 机理规则基线（必须可解释，先上线）

```
raw_signal = Σ_i (change_i × prior_weight_i × q_i) + seasonal_bias / 22 + news_sentiment × 0.2
signal     = clamp(raw_signal × 22 / max(1, Σ effective_weights), -100, 100)
bucket     = 按 §3.2 的 σ 自适应带对 raw_signal 分档
direction  = sign(bucket)（-1 / 0 / 1，与展示永远一致）
```

- **单位统一**：`seasonal_bias` 的单位是「信号分」，先除以 `22` 折算成期望涨跌幅（%），
  否则月度量级的先验（±2~3）会压倒日度外盘传导（±0.5），实测会把方向命中打到 34%。
  折算后季节性只做温和修正，`q=0` 品种若无外盘传导则通常落在震荡。
- **方向口径**：不采用 `sign(signal)` + `|signal|<12` 的近似；统一由 §3.2 分档带推出，
  避免「signal 偏空但卡片显示震荡」。
- **概率**：`Normal(exp_change, σ)` 对 ±震荡带积分并归一化；`confidence = max(p*)`，
  外盘缺失源 >2 个 ×0.7、事件日 ×0.8。
- **可追溯**：`contributor` 仅保留 `q>0` 的传导项（q=0 品种不展示传导行），
  每项含 `name/value/weight/q/contribution`，贡献之和回到 `exp_change`。
- 优点：零训练、天然可解释、随时可调；v1 已验证传导部分命中 57%~62%
- 定位：**兜底**。模型 B 不可用/过期时自动切到 A，并把置信度乘 0.8

### 5.2 Layer B · LightGBM 多分类

| 项 | 设定 |
|---|---|
| 目标 | 三分类：偏多（含强多）/ 震荡 / 偏空 |
| 特征 | §4 中除 `display_only` 外全部 + 品种 one-hot + 月份 |
| 样本 | 每品种独立训练（品种间机理差异大，共享样本会稀释信号）；样本不足时用板块池化 |
| 超参 | `num_leaves=15, min_data_in_leaf=40, lr=0.05, n_estimators≤400`，早停 |
| 类别不平衡 | `class_weight='balanced'`；震荡类占比通常 45%~55% |
| 输出 | 3 个概率，softmax |

- 数据量现实：单品种 4 年日线 ≈ 900 条 → **只够简单模型**。因此不追求复杂网络；样本积累到 2000+ 条后再评估 LSTM/Transformer。这一点必须诚实写进方案，避免"上神经网络但过拟合"。

### 5.3 Layer C · 融合

```
w_A, w_B ∝ exp(-logloss_A), exp(-logloss_B)   (最近 60 样本外)
final_p = w_A × p_A + w_B × p_B
```

- 任一模型缺失 → 单模型 + 置信度折减
- 融合权重每周更新一次，公式固定，避免人工干预

### 5.4 训练与版本

| 环节 | 规则 |
|---|---|
| 训练频率 | 每周一 03:00 重训（数据到上周五） |
| 版本号 | `gbm-YYYYMMDD-NN`，写入 `model_registry` |
| 上线门槛 | 样本外 Balanced Accuracy ≥ 基线 + 0.03，且 Brier ≤ 0.23，否则新版本只进 `shadow` |
| 回滚 | `status` 改回旧版本即可，API 立即生效（版本从 registry 读，不写死） |
| 影子模式 | 新版本先并行产出但不展示 1 周，比较与线上版本的差异 |

## 6. 回测协议（用户明确要求：严格按时间划分）

### 6.1 切分

```
|←———— 训练 500 日 ————→|← 验证 20 →|← 测试 20 →|  ← 滚动 step=20
                                    |←———— 训练 520 日 ————→|← 验证 20 →|← 测试 20 →|
...
|←———————————— 全部可用历史 ————————————→|← 永久 holdout 最近 60 日 →|
```

- **Walk-forward**：训练窗口滚动，绝不使用未来数据
- **永久 holdout**：最近 60 个交易日只在最终评估时使用一次，任何调参不得触碰
- 每折产出：命中率、Brier、logloss、ECE、按置信度分桶的命中率

### 6.2 防未来函数检查（CI 强制）

1. 每条 prediction 的 `asof` < `target_date 09:00`
2. 快照中所有数据时间戳 ≤ `asof`
3. 资讯情绪只取 `trade_date < target_date`
4. 外盘只用前一交易时段
5. 任一检查失败 → 回测报告标红，禁止上线

### 6.3 评估指标

| 指标 | 说明 | 门槛 |
|---|---|---|
| 方向命中率 | 排除震荡预测后的二分类命中 | ≥55% |
| Balanced Accuracy | 三类各自召回的平均 | ≥0.45（三分类） |
| Brier Score | 概率校准 | ≤0.23 |
| ECE | 可靠性曲线偏差 | ≤0.05 |
| 覆盖率 | 非震荡预测占比 | 如实报告，不追高 |
| 分品种命中率 | 逐品种 | 低于 50% 的品种自动降置信度 |

### 6.4 报告

每次回测输出 `docs/backtest/YYYYMMDD.md` + 同结构 JSON：结论、分品种表、可靠性曲线、失败案例分析（错在哪一环：外盘误判/季节性失效/资讯滞后）。

## 7. LLM 使用规范（只解释与抽取，不定方向）

| 用途 | 输入 | 输出 | 缓存 | 降级 |
|---|---|---|---|---|
| `explain_morning` | 贡献者明细 + 快照摘要 | 2~3 句中文解读 | `sha256(inputs)`，24h | 模板拼接（"布伦特 -1.31%，成本端偏空"） |
| `extract_event` | 资讯标题+正文 | 品种/方向/强度/环节/是否预期差/原文依据 | 按 doc_id，永久 | 规则词典 + 关键词 |
| `digest_summary` | 当日全品种预测 + 资讯摘要 | 简报正文 | 按 date | 模板渲染 |

**硬约束**：
- 不允许 LLM 输出方向数值或置信度——这些只来自 Layer A/B
- LLM 抽取的 `evidence` 必须能在原文中找到子串，否则该条抽取作废（防幻觉）
- 日预算 ¥5，超出后当日只走降级模板，并告警
- 所有调用写 `llm_call_log`（tokens、成本、缓存命中、耗时）

## 9. 从资讯到修订（预期差机制）

```
新资讯 → 关键词/品种识别 → LLM 抽取 {品种, 方向, 强度, 环节, 是否预期差, evidence}
        → 校验 evidence 在原文中 → 写 news_extract
        → 若 is_surprise 且 强度≥4:
             对比当前 Prediction 方向
             若方向相反 → 生成 PredictionRevision(signal 调整, reason=该资讯)
             发 SSE → 卡片出现「盘中修订」标记
```

- 修订**不覆盖**原预测，只追加，保留完整链路
- 当天收盘评分时，修订后的版本参与评分（因为用户看到的是修订后信息）
- 修订次数进监控：单品种单日 >3 次 → 说明资讯噪声大，告警

## 10. 数据质量与异常处理

| 场景 | 处理 |
|---|---|
| 某源连续 3 次失败 | `source.last_status=failed`，页面标灰，告警 |
| 行情价格跳变 >15% | 入库但标记 `anomaly`，不参与特征 |
| 外盘数据缺失 | 该传导贡献置 0，置信度折减，卡片标注「外盘缺失」 |
| 某品种连续 3 日无预测 | 告警（08:30 任务异常） |
| 资讯暴增（>500/小时） | 采样入库，避免 LLM 成本失控 |
| LLM 超预算 | 当日降级模板，记录告警 |
| 数据库连接失败 | API 返回 503 + `Retry-After`；worker 指数退避重试 |
