# 05 · 运维手册

> M7 交付物：告警含义、常见故障、回滚步骤、数据源失效替代方案。
> 适用：Render（api + worker）+ Supabase + Upstash 部署。

---

## 1. 环境变量

| 变量 | 必填 | 默认值 | 说明 |
|---|---|---|---|
| `APP_ENV` | 否 | `local` | `local` / `test` / `staging` / `production` |
| `DATABASE_URL` | **是** | — | PostgreSQL 连接串，`postgresql+asyncpg://` 开头；Supabase 给的 `?sslmode=require` 会自动转成 asyncpg 需要的 `?ssl=require` |
| `REDIS_URL` | **是** | — | Redis 连接串，`redis://` 或 `rediss://` 开头；Upstash 用 `rediss://` |
| `API_TOKEN` | 否 | `change-me-in-production` | admin 接口（模型切换/LLM 统计）的 `X-API-Token`；生产必须改 |
| `CORS_ORIGINS` | 否 | `["http://localhost:5173"]` | 允许跨域的前端域名列表（JSON 数组字符串） |
| `RUN_MIGRATIONS` | 否 | `1` | 容器入口是否执行 `alembic upgrade head`；API=1，worker=0 |
| `WORKER_HEARTBEAT_TTL_SEC` | 否 | `90` | worker 心跳 TTL；超过此值 `/ready` 报 worker degraded |
| `MODEL_DIR` | 否 | `models` | GBM 产物目录（相对仓库根，gitignored） |
| `LLM_API_KEY` | 否 | `None` | DeepSeek API Key；未配置时只用规则抽取，LLM 成本为 0 |
| `LLM_BASE_URL` | 否 | `https://api.deepseek.com` | LLM 接入地址 |
| `LLM_MODEL` | 否 | `deepseek-v4-flash` | 模型名 |
| `LLM_DAILY_BUDGET_CNY` | 否 | `5.0` | 单日 LLM 预算（元），达上限自动降级 |
| `LLM_PRICE_IN_CNY_PER_1K` | 否 | `0.001` | 输入单价（元/千 token） |
| `LLM_PRICE_OUT_CNY_PER_1K` | 否 | `0.002` | 输出单价（元/千 token） |

## 2. 探针与自愈

| 端点 | 用途 | 语义 |
|---|---|---|
| `GET /live` | 容器存活探针 | 不碰 db/redis，进程活着就 200；Render healthCheck 用此 |
| `GET /ready` | 业务就绪 | db/redis 故障 → 503；worker 心跳超 TTL → 200 `degraded`（不阻塞 API） |
| `GET /metrics` | Prometheus 指标 | 采集成功率 / 预测产出 / LLM 成本 / 滚动命中率 / 模型状态 / 心跳年龄 |

**自愈**：API 容器启动时自动 `alembic upgrade head`；worker 等待迁移就绪再启动（entrypoint 轮询 `alembic_version` 表）。Render 重启后 5 分钟内自愈（迁移 + 探针 + worker 心跳）。

**保活**：Render 免费 web 服务会休眠。用外部 cron（如 cron-job.org）每 5 分钟 `GET /live` 保活；worker 是独立服务，不休眠，定时任务不受影响。

## 3. 告警含义与定位

所有告警都能定位到具体**源 / 任务 / 品种**：

| 告警 | 来源 | 定位字段 | 排查步骤 |
|---|---|---|---|
| 数据源连续失败 | `/api/v1/sources` 的 `last_error` | `source.code` + `last_run_at` | 查 `fetch_log` 最近错误行；网络/反爬/源改版 |
| 单品种单日修订 >3 次 | `jobs/news/revision.py` `logger.error` + `/api/v1/revisions` 的 `alerts` | `variety_code` | 查 `prediction_revision` 按品种过滤；看 `trigger_doc` 是否重复资讯 |
| worker 心跳丢失 | `/ready` worker=degraded + `/metrics` `czce_worker_heartbeat_age_seconds` | — | worker 进程是否存活；Redis 是否可达；`arq jobs.worker.WorkerSettings` 日志 |
| LLM 成本超预算 | `/api/v1/admin/llm-stats` `degraded=true` | `date` | `llm_call_log` 按日聚合；是否缓存命中率骤降 |
| 模型命中率环比下降 | 周报 `recommendation=retrain` | `model_version` | `scorecard_snapshot` 对比两周；是否数据源异常导致特征漂移 |

## 4. 常见故障

| 现象 | 可能原因 | 处置 |
|---|---|---|
| `/ready` 503 db=error | DATABASE_URL 错或 Supabase 暂停 | 检查连接串；Supabase 免费版需每周登录保活 |
| `/ready` 503 redis=error | Upstash 连接串错或 TLS | `rediss://` 开头；检查 `REDIS_URL` |
| 08:30 无预测产出 | worker 未运行 / 特征快照失败 | 看 worker 日志 `build_snapshots` / `predict_daily`；手动跑一次确认 |
| 预测全为震荡（direction=0） | 外盘数据缺失（q=0 传导被降权） | `/api/v1/sources` 查外盘源；`collect_fred_dx` 日志 |
| SSE 前端收不到修订 | API 到 worker  Redis 不通 | worker 心跳正常则查 Redis；`/api/v1/revisions` 直接查库 |
| 详情抽屉无校准指标 | 无 active fusion 且无 backtest_run | 正常回退到规则版；`GET /api/v1/admin/models` 查 registry |

## 5. 模型回滚步骤

**目标**：旧模型版本 1 分钟内生效（同步事务，实际 <1s）。

```bash
# 1. 查看当前模型版本与状态
curl -H "X-API-Token: $API_TOKEN" https://<api>/api/v1/admin/models

# 2. 回滚到指定旧版本（其余 fusion/gbm 自动 retired）
curl -X POST -H "X-API-Token: $API_TOKEN" \
  https://<api>/api/v1/admin/models/<old-version>/activate

# 3. 验证：该版本 status=active，其余 retired
curl -H "X-API-Token: $API_TOKEN" https://<api>/api/v1/admin/models
```

引擎每次预测**实时读 `model_registry`**，切换后下一批预测立即使用新版本，无需重启。

## 6. 数据源失效替代方案

| 数据源 | 失效现象 | 替代方案 |
|---|---|---|
| 新浪实时行情 | 价格时间戳不变 / 空返回 | 接口化 `BaseCollector`，可换 AKShare / 东财；q 缺失时规则层自动降置信度 |
| 新浪外盘 hf_DX | 已停供（空返回） | 已改用 FRED `DTWEXBGS` 日线（`collect_fred_dx`） |
| 郑商所仓单日报 | 412 / 文件格式变 | `CzceReceiptCollector` 表头驱动解析；格式变时改表头映射即可 |
| 金十/东财/新浪资讯 | 反爬 / 改版 | 四路独立，一路失败不影响其余；规则抽取保守，宁可少抽不误抽 |
| FRED 美元指数 | 接口限流 | 日线频率低，限流概率小；失败时 `industry_metric` 对应字段为 null，特征层按 null 处理 |
